# Spec Delta

## Purpose

将串口字节流按真实报文帧组装并写入日志，使每条报文独占一行，带有精确时间戳与明确的收发方向，供现场排查和事后分析使用。

## ADDED Requirements

### Requirement: 帧边界自动识别
系统 SHALL 按报文帧（而非读取块）组装字节：二进制串口的帧间静默阈值 MUST 依据当前波特率按 3.5 个字符时间计算（高波特率下采用规范固定值）；以 `:` 起始的 ASCII 帧 MUST 以起始符与结束 CRLF 界定。一个完整报文帧在任何情况下都不得被拆成多条日志。

#### Scenario: 长应答帧跨多个读取周期
- **WHEN** 一个 25 字节应答帧在 19200 波特下持续约 14ms、跨越多个轮询周期到达
- **THEN** 日志中该帧完整呈现为一行 25 字节，不产生中间时间戳

#### Scenario: 帧间静默后开始新帧
- **WHEN** 总线上静默达到 3.5 字符时间后出现下一帧字节
- **THEN** 系统结束当前帧并以新字节起始下一帧

#### Scenario: ASCII 帧界定
- **WHEN** 总线上出现 `:` 起始、CRLF 结束的 ASCII 报文
- **THEN** 该报文按起止符组装为一帧，不受静默时长影响

### Requirement: 每帧记录时间戳
系统 SHALL 为每条帧记录时间戳，分辨率 MUST 达到毫秒级，时间戳取自该帧首字节到达时刻。

#### Scenario: 请求应答时间差可辨
- **WHEN** 请求帧与约 40ms 后到达的应答帧分别落盘
- **THEN** 两条日志的时间戳之差与实际收发间隔一致

### Requirement: 收发方向与角色标识
系统 SHALL 在每条报文行标注方向：本设备驱动发出的报文 MUST 标为 `TX`，总线监听得到的报文 MUST 标为 `RX`；可判定为 Modbus 请求/应答时 MUST 进一步标注 `REQ`/`RSP`。

#### Scenario: 被动监听主从通信
- **WHEN** 设备在总线上监听到主站请求随后从站应答
- **THEN** 两条日志分别标注 `RX-REQ` 与 `RX-RSP`

### Requirement: 出站帧统一记录
系统 SHALL 使所有发送路径（测试发送、周期发送、控制台发送、网络/蓝牙下发）作为出站帧记录为 TX；发送后 MUST 丢弃本设备自身的回环数据，避免同一帧被重复记录。

#### Scenario: 网络下发只记一次
- **WHEN** 一条 TCP 客户端下发报文经本设备发出
- **THEN** 日志中仅出现一条该报文的 `TX` 记录，不出现内容相同的 `RX` 记录
