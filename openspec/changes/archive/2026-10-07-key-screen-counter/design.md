# Design

## Context

屏幕背光由 XL9555 扩展 IO 的 P07 控制，K1/K2 两个物理按键同样挂在 XL9555 上（P04/P03，低电平有效），原有按键扫描是阻塞式短按扫描、由 400ms 的 UI 定时器驱动，无法精确判定 2 秒长按。配置使用带版本号的 NVS blob，当前为 v2。系统统计计数器（logger 与 bridge 各若干项）均为 uint32。约束不变：BLE/WiFi 初始化顺序固定、内部内存紧张（AGENTS.md）。

## Goals / Non-Goals

**Goals:**
- 长按判定不依赖阻塞延时，扫描周期足够精细，短按行为与现有 UI 兼容。
- 息屏/唤醒可靠，唤醒不需要重建显示。
- 计数溢出被永久消除，且热路径零额外开销。

**Non-Goals:**
- 不实现多级亮度、PWM 调光。
- 不改变统计口径（统计什么字节/帧不变），只改变容量。
- 不把运行期计数器写入 NVS（重启后统计归零的行为保持不变）。

## Decisions

### 1. 独立屏幕管理任务 + 状态机
新增 20ms 周期的屏幕管理任务，一次 I2C 事务读回 K1/K2 电平：原始电平先经过 40ms 稳定确认（消抖），确认按下后记录起始时间，持续按下达到 2s 时执行一次屏幕动作并标记“长按已消费”；松开时若未消费则作为短按交给 UI。相比沿用阻塞扫描，20ms 粒度保证长按误差 ≤40ms，且不会因为按键消抖阻塞任何任务。
备选：GPIO 中断 + 软件定时——XL9555 按键走 I2C 扩展、无单线中断到主控（INT 未使用），中断方案需要额外启用扩展芯片中断线，改动大，放弃。

### 2. 息屏只关背光，面板与显存保持供电
背光关闭即可达到息屏目的，LCD 面板不断电，LVGL 继续运行；唤醒只是重新拉高背光，无重绘、无延迟。这也使计时逻辑简单（唤醒即重置活动时间）。
备选：关闭显示电源/反初始化面板——唤醒慢、风险高，放弃。

### 3. 跨线程短按用“标志 + UI 定时器”交接
屏幕任务不在 LVGL 线程，不能直接操作控件。短按仅写入一个 volatile 标志，UI 任务的 50ms 定时器在 LVGL 上下文读取并执行标签切换。避免了跨任务操作 LVGL 的线程安全问题。

### 4. 64 位高位扩展而非循环计数
统计计数器直接扩为 uint64_t：自增指令与 32 位形式开销相同、无分支，2^64 容量在任何现实场景不可达，等同永久消除溢出。相比“循环计数（归零回绕）”，回绕本身仍是溢出、会破坏统计连续性；相比“高位单独扩展字段”，单一 64 位变量更简单、不会产生高低位一致性问题。
备选：饱和计数（封顶停在最大值）——封顶后统计失真，放弃。

### 5. 配置项与 blob 版本升级的兼容
`screen_auto_off` 加入 app_settings 结构体与 blob，版本升 v3；读取时同时接受 v2（旧大小）与 v3，v2 缺失该字段按默认开启处理。config.json 快照与导入同步增加该字段，缺失按 true、存在必须布尔。
备选：直接升版本拒绝旧 blob——会丢失现场配置，放弃。

### 6. 变化检测改为快照与磁盘文件比对
自动检测每 2 秒把当前 canonical 快照与磁盘 config.json 实际内容比对，任何差异（运行期修改、字段缺失、文件缺失）都触发导出。这样新增字段能自动补进既有文件，不依赖“记住上次快照”，系统自收敛。

## Risks / Trade-offs

- [息屏后用户不知如何点亮] → K2 长按 2s；切换时指示灯闪烁 + 日志反馈。
- [长按边界抖动] → 消抖只影响按下/松开的确认，持续按住阶段不重置时长计时。
- [新增任务增加内存占用] → 任务栈 4KB，不新增内部 BSS 大缓冲（无大的静态数组），实测 BLE/WiFi/httpd 共存正常。
- [配置文件读写冲突] → 复用 app_fs_lock 与原子替换（临时文件 → 备份 → remove → rename）。
